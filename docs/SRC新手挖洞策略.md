## 一、前言：为什么SRC挖洞是新手最佳起点

SRC（Security Response Center，安全应急响应中心）是企业官方接收外部漏洞的平台。对零基础小白来说，SRC挖洞的核心优势是：**合法、低门槛、有现金回报、比刷靶场更接近真实场景**。

许多新手坚持练习1-2周就能挖到第一个有效漏洞。投入时间建议：每天1-2小时，1-2个月可稳定出低危漏洞。

> **核心忠告**：先看规则！不看范围挖漏洞 = 白干！未经授权的测试「点到为止」，证明危害即可。

## 三、最高通过率的漏洞类型（2026年数据）

### 3.1 新手最容易通过的漏洞类型（按通过率排序）

| 排名 | 漏洞类型 | 通过率 | 难度 | 说明 |
|------|---------|-------|------|------|
| 1 | **信息泄露** | ~80% | ⭐ | 备份文件泄露、目录遍历、错误信息暴露——最常见、验证最直接 |
| 2 | **越权/未授权访问** | ~75% | ⭐⭐ | 水平/垂直越权，通过修改ID或cookie测试 |
| 3 | **反射型XSS** | ~65% | ⭐ | 搜索框、参数反射，验证即见效 |
| 4 | **逻辑漏洞**（并发/绕过） | ~60% | ⭐⭐ | 优惠券多发、订单篡改、验证码绕过 |
| 5 | **弱口令** | ~60% | ⭐ | 后台/测试机弱口令 |
| 6 | **简单SQL注入** | ~50% | ⭐⭐ | 参数点注入（不要脱库！） |
| 7 | **CSRF** | ~45% | ⭐⭐ | 缺少token验证 |
| 8 | **文件上传** | ~40% | ⭐⭐⭐ | 需绕过黑白名单 |

### 3.2 核心结论

- **信息泄露和未授权访问**是新手通过率最高的两类漏洞。原因是验证逻辑简单（直接访问即看到结果），不需要复杂利用工具。
- **逻辑漏洞**是SRC前辈最推荐的入门方向——"很多SRC大佬新手阶段都是从逻辑漏洞开始的"。每个网站或多或少存在并发逻辑漏洞。
- Web漏洞占SRC漏洞总量的**70%以上**，新手应优先聚焦。
- 2026年新趋势：**AI提示词注入、云原生漏洞**开始在企业SRC中出现。

### 3.3 新手挖洞优先级排序

```
第一优先：信息泄露（备份文件 / .git泄露 / 目录遍历）
第二优先：未授权访问（接口无鉴权）
第三优先：反射型XSS（搜索框/参数反射）
第四优先：逻辑漏洞（优惠券/支付/密码重置）
第五优先：简单SQL注入（参数点）
```

## 四、真实案例：新手第一次挖到漏洞的故事

### 案例1：大学生张三 → 电商平台越权（高危）

**背景**：某大学网络安全社团成员，学习SRC挖洞第3周。

**过程**：
1. 在目标电商平台注册两个账号（A和B）
2. 用Burp Suite抓取A账号查看订单的请求包
3. 发现订单ID参数 `order_id=12345`
4. 修改为 `order_id=67890`（B账号的订单）
5. 成功返回B账号的收货地址、手机号等敏感信息

**结果**：提交后3小时审核通过，判定为「高危-水平越权」，获得奖金¥2,000。

**关键点**：越权漏洞验证逻辑简单、危害明确、审核通过快。

### 案例2：Subs（F0tsec团队）→ 3天挖7个漏洞

**背景**：安全新手，在腾讯云社区分享经验。

**成果**：3天内提交 4个低危 + 2个中危 + 1个严重漏洞。

**核心方法**：
1. 先通过响应头信息泄露发现CMS版本号
2. 搜索该CMS版本对应的公开漏洞
3. 下载最新源码进行代码审计
4. 发现SQL注入点

**关键技巧**："不是众测的话，挖到漏洞后不要直接提交，先思考如何扩大战果。比如XSS能否结合CSRF变成蠕虫？测试机器弱口令能否Getshell？"

### 案例3：某安全新手 → 573万用户信息泄露（高危）

**过程**：
1. 目标系统前端空白，后端接口多返回403
2. 通过JS文件反向查找隐藏API接口
3. 发现某接口未授权访问
4. 遍历参数后返回大量用户数据

**结果**：高危漏洞，企业紧急修复。

**启示**：不要因为页面"空白"就放弃，JS中往往藏着关键接口。

## 五、报告被驳回的十大原因（附解决方案）

### 5.1 驳回原因排行榜

| 排名 | 驳回原因 | 占比 | 解决方案 |
|------|---------|------|---------|
| 1 | **无法复现**（复现步骤不清晰、截图模糊） | ~35% | 每步截图，用红框标记关键操作 |
| 2 | **不在测试范围**（未仔细读规则） | ~20% | 提交前核对平台允许的域名/产品 |
| 3 | **无实际危害**（伪漏洞） | ~15% | 确认泄露的是敏感信息而非无关数据 |
| 4 | **重复提交**（已有人发现） | ~10% | 提交前搜索平台已有报告 |
| 5 | **报告不规范**（缺少核心要素） | ~8% | 使用标准模板 |
| 6 | **漏洞证明不足**（缺少关键截图） | ~5% | 至少3张清晰截图 |
| 7 | **危害夸大**（实际影响被放大） | ~3% | 实事求是描述危害 |
| 8 | **修复建议无法落地** | ~2% | 提供具体可操作的修复方案 |
| 9 | **使用攻击性工具破坏业务** | ~1% | 禁止DDoS、脱库、删改数据 |
| 10 | **超出授权范围测试** | ~1% | 严格遵守授权边界 |

### 5.2 新手最易犯的四大错误

**错误一：忽视平台规则**
- 后果：攻击未授权系统，轻则驳回，重则法律责任
- 对策：提交前逐条阅读《漏洞提交规范》《挖掘范围》

**错误二：报告写得太模糊**
- 后果：审核人员无法复现
- 对策：假设审核员完全不知道你在做什么，用最朴素的文字描述每一步

**错误三：盲目追求高危漏洞**
- 后果：长期挖不到，打击信心
- 对策：从低危、信息泄露入手，先建立正向反馈

**错误四：过度依赖自动化工具**
- 后果：遇到WAF束手无策
- 对策：先学漏洞原理，再用工具辅助

## 六、一份能通过的漏洞报告——完整模板与示例

### 6.1 报告结构（通用模板）

```
【漏洞标题】：【漏洞类型】+ 漏洞位置
例：【信息泄露】XX平台数据库备份文件可被任意下载

【漏洞类型】：信息泄露 / 未授权访问 / 反射型XSS / SQL注入

【漏洞描述】：简要说明漏洞的危害和影响范围

【影响范围】：具体域名 / URL / 接口

【复现步骤】：
1. 访问URL：https://xxx.com/backup/DB_bak_202605.sql
2. 页面直接返回数据库备份文件
3. 下载后打开，包含用户表（手机号、密码hash等）

【漏洞危害】：攻击者可获取××条用户敏感数据，导致信息泄露

【修复建议】：
1. 删除或迁移备份文件至不可访问路径
2. 配置Nginx/Apache禁止访问.sql后缀文件
3. 对敏感目录添加访问鉴权

【截图证明】：（至少3张：漏洞入口、复现过程、危害证明）
```

### 6.2 实际报告示例

#### 示例1：信息泄露报告

```
【漏洞标题】：【信息泄露】XX电商平台/api/order/list接口存在未授权访问

【漏洞类型】：未授权访问

【漏洞描述】：该接口未做任何鉴权校验，任意用户可直接访问查看全平台订单信息，包括用户姓名、手机号、收货地址等敏感字段。

【影响范围】：https://xxx.com/api/order/list

【复现步骤】：
1. 打开浏览器（无需登录）
2. 访问 https://xxx.com/api/order/list?page=1&size=20
3. 页面直接返回JSON数据，包含订单号和用户手机号

【漏洞危害】：
- 任意攻击者可批量获取平台用户订单数据
- 预计泄露数据量：10万+ 条订单记录
- 可用于精准诈骗、信息倒卖

【修复建议】：
1. 对/api/order/list接口添加登录鉴权
2. 接口返回数据脱敏（手机号中间4位隐藏）
3. 限制接口频率，防止批量爬取

【截图证明】：（3张截图，含URL栏、返回数据、敏感信息特写）
```

#### 示例2：越权漏洞报告

```
【漏洞标题】：【水平越权】XX应用修改密码接口可越权修改他人密码

【漏洞类型】：水平越权

【漏洞描述】：修改密码接口仅通过前端提交的用户ID进行身份识别，未校验修改者与目标用户的一致性，导致任意登录用户可修改其他用户密码。

【影响范围】：https://xxx.com/api/user/reset-password

【复现步骤】：
1. 登录账号A，获取cookie：token=abc123
2. 抓取修改密码请求包：
   POST /api/user/reset-password
   Cookie: token=abc123
   Body: user_id=10001&new_password=Test123456
3. 将Body中的user_id改为10002（其他用户）
4. 发送请求，返回 {"code":200, "msg":"成功"}
5. 使用账号B（user_id=10002）+ 新密码 Test123456 成功登录

【漏洞危害】：
- 任意登录用户可修改平台任意用户密码
- 可直接接管管理员账号（如admin账号user_id=1）
- 导致全平台用户账号沦陷

【修复建议】：
1. 修改密码时从cookie/session中获取当前登录用户ID
2. 不允许前端传入user_id参数
3. 关键操作增加二次验证（原密码或验证码）
```

## 七、时间高效挖掘策略（先扫什么？怎么排优先级？）

### 7.1 单次挖洞时间分配（推荐2小时）

```
前30分钟：信息收集（决定成败的关键）
 ├─ 5分钟：子域名收集（OneForAll / Subfinder）
 ├─ 10分钟：资产测绘（FOFA / Hunter 搜索目标）
 ├─ 5分钟：技术栈识别（Wappalyzer插件）
 └─ 10分钟：端口扫描（Nmap -T4 -F 目标IP）

中间60分钟：漏洞探测
 ├─ 15分钟：目录扫描（Dirsearch → 敏感文件/后台）
 ├─ 15分钟：接口测试（Burp抓包分析功能点）
 ├─ 15分钟：逻辑漏洞测试（越权/未授权/并发）
 └─ 15分钟：自动化扫描（Xray / Nuclei）

最后30分钟：验证与记录
 ├─ 15分钟：复现验证（不同环境重复2-3次）
 ├─ 10分钟：截图留存（入口、过程、证明）
 └─ 5分钟：编写报告初稿
```

### 7.2 扫描优先级金字塔

```
第一层（最先扫）：
  敏感文件泄露路径
    → /backup.sql, /.git/config, /WEB-INF/web.xml
    → /db.sql, /config.php.bak, /phpinfo.php
    → /robots.txt（隐藏路径线索）
  
第二层（其次扫）：
  目录/后台路径
    → /admin/, /manager/, /system/
    → /api/, /swagger-ui.html, /actuator/
    → /upload/, /download/, /file/

第三层（然后扫）：
  未授权接口
    → 所有API端点（尝试直接访问）
    → 用户信息接口（/api/user/list, /api/user/info）
    → 日志/订单接口（/api/log, /api/order）

第四层（最后扫）：
  参数测试
    → 登录框（SQL注入、任意密码重置）
    → 搜索框（XSS、SQL注入）
    → 评论/反馈（存储型XSS）
    → 支付/优惠券（金额篡改、并发问题）
```

### 7.3 边缘资产优先原则

**不要攻击主站！** 主站的防护最严、竞争最大。优先测试：

1. **子域名**（subdomain.xxx.com）→ 防护通常弱于主站
2. **小程序内嵌H5** → 审核不严，漏洞留存率高
3. **旧版系统**（old.xxx.com, v1.xxx.com）→ 可能停止维护
4. **新上线功能/活动页面** → 迭代快，安全检查不到位
5. **测试环境**（test.xxx.com, dev.xxx.com）→ debug开启、弱口令常见
6. **边缘IP段** → 测试机器常有弱口令

> "在边缘段中一般会存在N台测试机器，测试机器是我们最好的突破口。因为测试机器往往不会关闭debug、并且登录账号通常为弱口令。"

### 7.4 工具链配置

**必须掌握的核心工具**：

| 工具 | 用途 | 学习时间 |
|------|------|---------|
| Burp Suite（社区版） | 抓包改包、重放、参数测试 | 3天 |
| Dirsearch | 目录/敏感文件扫描 | 1天 |

### 7.5 日常高效挖洞流程（30分钟速扫版）

如果时间有限，每天只做30分钟的快速测试：

```
1. FOFA搜索目标子域名（5分钟）
   → app="目标企业" + 新增子域名

2. 快速目录扫描（10分钟）
   → Dirsearch + 常用敏感文件字典

3. 检查3个高概率点（10分钟）
   → 未授权API
   → 备份文件路径
   → 后台登录页面弱口令

4. 随手测试（5分钟）
   → 任意URL参数加'
   → 修改cookie/header的user_id
```

## 九、成长路线图（0→3个月）

### 第1周：打基础
- 掌握HTTP协议基础（请求方法、状态码、请求头）
- 安装Burp Suite并学会抓包改包
- 了解XSS、SQL注入、信息泄露的基本原理
- 注册漏洞盒子，阅读平台规则

### 第2周：第一次出洞
- 用Dirsearch扫描目录找敏感文件
- 测试未授权接口（重点方向）
- 尝试简单的XSS（搜索框反射）
- **目标：提交第一个低危漏洞**

### 第3-4周：稳定输出
- 深入学习越权漏洞
- 学习逻辑漏洞（优惠券/密码重置/支付）
- 尝试补天公益SRC
- **目标：每周提交1-2个有效漏洞**

### 第2个月：进阶
- 学习SQLMap使用
- 学习JS逆向找隐藏接口
