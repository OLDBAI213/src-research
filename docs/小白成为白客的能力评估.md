## 二、环境搭建方案对比

### 方案 A：WSL2 + Kali Linux ⭐ 推荐

| 维度 | 评估 |
|------|------|
| 安装复杂度 | 中等。`wsl --install -d kali-linux` 安装基础系统 → `apt install kali-linux-headless` 装渗透工具 |
| 工具覆盖 | 全。600+ 渗透工具预装（nmap/sqlmap/nuclei/metasploit/burp...） |
| AI Agent 友好度 | **高**。Hermes 的 terminal 默认就是 bash，WSL2 的 bash 和 host bash 一样可调用 |
| 文件互通 | 好。WSL2 文件可通过 `\\wsl$\kali-linux\` 或 `/mnt/e/` 访问 |
| 网络模式 | WSL2 NAT 模式，Windows host 可访问 WSL2 IP |
| 缺点 | 需要 Windows 功能开启（Virtual Machine Platform），首次安装需重启 |
| **适合小白** | **最推荐**——一条命令装系统，apt 装工具，terminal 直接调 |

**操作步骤**（4步，约30分钟）：
```
1. wsl --install -d kali-linux
2. 重启 + 设置用户名密码
3. sudo apt update && sudo apt install -y kali-linux-headless
4. nmap/sqlmap/nuclei 即装即用
```

### 方案 B：Docker Desktop + Kali 容器

| 维度 | 评估 |
|------|------|
| 安装复杂度 | **高**。Docker Desktop 安装包 500MB+，需要 WSL2 后端运行，配置繁琐 |
| 资源占用 | 大。Docker Desktop 本身吃 2GB+ 内存 |
| AI Agent 友好度 | 中。需要 `docker exec` 进入容器执行命令，多一层抽象 |
| 缺点 | 非必要不要选，Docker 对渗透测试是"额外包装"而非增益 |
| **结论** | ❌ 不推荐。除非你已经装了 Docker Desktop，否则别为渗透专门装它 |

### 方案 C：原生 Windows 工具

| 维度 | 评估 |
|------|------|
| Nmap for Windows | ✅ 有官方 Windows 安装包，含 Npcap 驱动 |
| SQLMap | ✅ Python 写的，pip install sqlmap 即可 |
| Nuclei | ✅ Go 写的，下载 Windows 二进制即可 |
| Burp Suite | ✅ 有 Windows 版 Java 安装包 |
| 缺点 | 各自独立安装，没有统一的包管理；某些工具（如 Metasploit）Windows 支持差 |
| **结论** | 可行但零散。适合"只缺个别工具"的场景，不适合完整渗透环境 |

### 最终建议

```
推荐顺序：WSL2 + Kali > 原生 Windows 工具 > Docker
原因：WSL2 对 Hermes 的 terminal 最友好，工具最全，维护成本最低
```

## 三、Python 工具集成分析

### Nmap

| 方式 | 说明 |
|------|------|
| `python-nmap` 库 | 封装了 nmap 命令行，返回结构化结果。需要系统先装 nmap |
| `subprocess.run(['nmap', ...])` | 直接调命令行，自己解析 XML/JSON 输出 |
| `libnmap` 库 | 另一个 Python nmap 封装，支持结果解析 |

**实战示例**：
```python
import nmap
nm = nmap.PortScanner()
results = nm.scan('target.com', '22,80,443')
# results 是字典，可直接 JSON 序列化
```

### SQLMap

| 方式 | 说明 |
|------|------|
| `sqlmap` pip 包 | 其实是把 sqlmap 源码装成命令行工具，不是 API 库 |
| SQLMap API | sqlmap 自带 RESTful API (`sqlmapapi.py`)，可远程调 |
| subprocess 驱动 | `subprocess.run(['sqlmap', '-u', url, '--batch'])` |

**关键点**：SQLMap **没有官方的 Python API 库**。标准做法是：
1. 启动 `sqlmapapi.py` 服务（HTTP API）
2. 通过 requests 发任务、查状态、取结果
3. 或者直接用 subprocess 跑命令行

### Nuclei

| 方式 | 说明 |
|------|------|
| `PyNuclei` 库 | 社区封装的 Python 库，需要本机装 nuclei 二进制 |
| subprocess 驱动 | `subprocess.run(['nuclei', '-u', url, '-json'])` |

### Burp Suite

| 方式 | 说明 |
|------|------|
| Burp REST API | Burp Pro 有 REST API（需付费许可） |
| Montoya API | Burp 的 Java API，需要 Jython 或 Java 桥接 |
| 不适合 AI Agent | 需要 GUI 操作，Pro 版付费，不建议自动化集成 |

### 结论

```
所有工具的本质接口都是：subprocess + 命令行
Python 库只是"帮你拼命令、帮你解析输出"的包装层
所以核心需求只有一条：本机装了这些工具的二进制文件
```

## 四、SRC 平台访问分析

### 补天 (butian.net)

| 项目 | 详情 |
|------|------|
| 注册条件 | 手机号 + 邮箱 + 实名认证（身份证） |
| 实名认证 | **必须**。上传身份证正反面，人脸验证 |
| 是否有 API | **无公开 API**。所有操作通过 Web 页面进行 |
| 提交方式 | Web 表单：漏洞标题、类型、等级、URL、漏洞详情、复现步骤、截图/PoC |
| 自动化可能性 | 需要浏览器自动化（Selenium/CDP）+ 模拟登录 |
| 奖金发放 | 银行汇款，需绑定真实银行卡 |
| 关键门槛 | **实名认证需要人类身份信息**，AI Agent 无法独立完成 |

### 漏洞盒子 (vulbox.com)

| 项目 | 详情 |
|------|------|
| 注册条件 | 手机号 + 邮箱 |
| 实名认证 | **必须**（身份证 + 银行卡绑定） |
| 是否有 API | **无公开 API** |
| 提交方式 | Web 表单，类似补天 |
| 自动化可能性 | 有开源项目 `src_script` 用 Selenium 半自动提交 |
| 关键门槛 | 同样需要人类实名 |

### 核心结论

> **SRC 平台有两个不可逾越的门槛：**
> 1. 注册需要实名认证（身份证 + 人脸/银行卡）——这是法律要求，不是技术问题
> 2. 没有任何公开 API——所有操作只能通过浏览器进行

**可行路径**：
- 由人类完成注册和实名认证
- AI Agent 可在人类授权下，通过浏览器自动化（Chrome CDP）完成漏洞提交
- 现有开源项目（如 `ftsec-ldh/src_script`）已实现漏洞盒子的半自动提交——说明浏览器自动化提交是可行的

## 五、不需要任何新工具，现在就能做的事

这是最重要的部分。在装任何工具之前，我（小白）现在就能做的信息收集工作：

### 1. 子域名枚举（被动式）

| 方法 | 工具 | 可行性 |
|------|------|--------|
| 搜索引擎语法 | `web_search("site:target.com")` | ✅ 立即可用 |
| 证书透明度 (CRT.sh) | `web_extract("https://crt.sh/?q=%25.target.com")` | ✅ 立即可用 — 这是最有效的被动子域名发现方式 |
| DNS 查询 | terminal: `nslookup sub.target.com` | ✅ 有限但可用 |
| GitHub 搜索 | `search_code("target.com")` 搜配置文件 | ✅ 立即可用 |

### 2. HTTP 服务探测

| 方法 | 工具 | 可行性 |
|------|------|--------|
| 发送 HTTP 请求 | `requests.get("https://target.com")` | ✅ 立即可用 |
| 获取响应头 | `requests.head()` + 分析 Server/Set-Cookie | ✅ 立即可用 |
| 目录/路径探测 | Python for 循环测路径 | ✅ 需要写脚本，但纯 Python 可做 |
| 响应分析 | 分析 status code / content-length / 标题 | ✅ 立即可用 |

### 3. DNS 信息收集

| 方法 | 可行性 |
|------|--------|
| `nslookup target.com` — A 记录 | ✅ |
| `nslookup -type=MX target.com` — 邮件服务器 | ✅ |
| `nslookup -type=TXT target.com` — SPF/DKIM | ✅ |
| `nslookup -type=NS target.com` — 域名服务器 | ✅ |

### 4. GitHub 泄露凭据搜索

```python
# 通过 MCP 的 search_code 可搜索：
# "target.com password" "target.com api_key" "target.com secret"
# "target.com" filename:.env  "target.com" filename:config
# "target.com" language:sql 中的连接字符串
```

这绝对是**最高价值的信息收集方式**——GitHub 泄露是真实存在的、高频率的、可自动化的。

### 5. Web 技术栈识别

```python
# 通过 response headers 识别
# Server, X-Powered-By, Set-Cookie 等
# 加上页面特征关键词匹配
r = requests.get("https://target.com")
# 分析 r.headers, r.text 判断 CMS/框架/版本
```

### 6. 边缘信息收集

| 方法 | 可行性 |
|------|--------|
| 搜索 "target.com 漏洞" | ✅ web_search 可发现历史漏洞 |
| 搜索 "target.com 后台" | ✅ 搜索引擎语法 |
| 搜索 IP 段归属 | ✅ web_search |
| 爬招聘信息找技术栈 | ✅ web_extract |

### 现在就能做的一条完整信息收集流水线：

```
target = "example.com"

# 1. 子域名收集
被动: crt.sh + 搜索引擎语法 + GitHub 搜索
结果: 子域名列表

# 2. 存活检测 + HTTP 指纹
for each subdomain:
    requests.get("https://"+subdomain, timeout=5)
    记录: status_code, headers, 页面标题, body长度

# 3. 技术栈识别
分析 headers + 页面特征
识别: CMS/框架/版本/中间件

# 4. GitHub 泄露搜索
search_code: target 相关泄露信息

# 5. DNS 枚举
nslookup: 所有发现的子域名

# 6. 汇总报告
输出: 攻击面地图
```

**不能做的事（缺工具时）：**
- ❌ 端口扫描（需要 nmap）
- ❌ 漏洞扫描（需要 nuclei/sqlmap）
- ❌ WAF 指纹识别（需要专业工具）
- ❌ 目录爆破（无 dirsearch/gobuster）
- ❌ 主动 SQL 注入测试（需要 sqlmap）
- ❌ 批量子域名爆破（需要 dnsx/dnsrecon）

## 八、诚实总结：我能做什么，不能做什么

### 我能做的 ✅
- **信息收集**：被动子域名发现、HTTP 指纹、技术栈识别、DNS 查询
- **GitHub 泄露搜索**：这是当前最高价值的能力
- **编写渗透脚本**：Python 全栈，能写任何自动化逻辑
- **浏览器自动化**：Chrome CDP 可以完成注册、登录、提交等操作
- **报告生成**：LLM 可以把技术发现转化为人类可读的漏洞报告

### 我不能做的 ❌
- **没有工具做主动扫描**：没有 nmap/sqlmap/nuclei，我无法扫描端口、检测 SQL 注入、运行漏洞模板
- **无法独立注册 SRC 平台**：实名认证需要人类的身份证和人脸
- **无法做底层网络操作**：没有 Scapy、netcat、Raw Socket
- **不能攻击未经授权的目标**：这是法律问题，不是技术问题

### 最诚实的说法

> **如果明天就要开始挖 SRC：**
> - 最快路径：装 WSL2 + Kali（1小时）→ 跑 nuclei 扫描 → 找到漏洞 → 人类提交
> - 纯 AI Agent 独立完成：**不可能**，因为 SRC 注册需要人类实名认证
> - AI Agent + 人类协作：**完全可行**，人类负责注册和授权，AI 负责扫描、分析、生成报告、自动化提交
