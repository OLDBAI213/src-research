## 1. 《网络安全法》关于渗透测试的核心条款

《中华人民共和国网络安全法》（2025年修订版，2026年施行）中，以下条款直接与渗透测试/漏洞挖掘相关：

### 第24条（原第22条）——产品漏洞报告义务

> 网络产品、服务应当符合相关国家标准的强制性要求。网络产品、服务的提供者不得设置恶意程序；**发现其网络产品、服务存在安全缺陷、漏洞等风险时，应当立即采取补救措施，按照规定及时告知用户并向有关主管部门报告。**

🔍 **对白帽子的意义**：这条规定了厂商/运营者的漏洞修复义务，为白帽子向厂商提交漏洞提供了法律上的正当性基础——厂商有义务接收并修复漏洞报告。

### 第27条（原第25条）——应急处置义务

> 网络运营者应当制定网络安全事件应急预案，**及时处置系统漏洞、计算机病毒、网络攻击、网络侵入等安全风险**；在发生危害网络安全的事件时，立即启动应急预案，采取相应的补救措施，并按照规定向有关主管部门报告。

### 第28条（原第26条）——发布安全信息的合规要求

> 开展网络安全认证、检测、风险评估等活动，**向社会发布系统漏洞、计算机病毒、网络攻击、网络侵入等网络安全信息，应当遵守国家有关规定。**

🔍 **对白帽子的意义**：这条直接关系到漏洞披露。向公众发布漏洞信息必须"遵守国家有关规定"，不能随意公开发布。

⚠️ **违反后果**：第65条规定，违反第28条的，责令改正，警告，可处1万-10万元罚款；拒不改正或情节严重的，处10万-100万元罚款，并可责令暂停相关业务、关闭网站。

### 第29条（原第27条）——**最关键的安全红线条款**

> **任何个人和组织不得从事非法侵入他人网络、干扰他人网络正常功能、窃取网络数据等危害网络安全的活动**；不得提供专门用于从事侵入网络、干扰网络正常功能及防护措施、窃取网络数据等危害网络安全活动的程序、工具；明知他人从事危害网络安全的活动的，不得为其提供技术支持、广告推广、支付结算等帮助。

🔍 **对白帽子的意义**：这是网络安全法中的"**绝对禁止条款**"。"非法侵入"是判断白帽子行为合法与非法的核心标准。**没有获得授权，任何"侵入"行为都可能落入此条款的规制范围。**

⚠️ **违反后果**：第66条规定——
- 尚不构成犯罪的：没收违法所得，处5日以下拘留，可并处5万-50万元罚款；
- 情节较重的：处5-15日拘留，可并处10万-100万元罚款；
- **受到治安管理处罚的人员，5年内不得从事网络安全管理和网络运营关键岗位工作；**
- **受到刑事处罚的人员，终身不得从事网络安全管理和网络运营关键岗位工作。**

## 2. 《刑法》相关罪名与入罪标准

渗透测试/漏洞挖掘最常触犯的刑法罪名，集中在《刑法》第285条和第286条。

### 2.1 《刑法》第285条第1款——非法侵入计算机信息系统罪

| 项目 | 内容 |
|------|------|
| **对象** | **国家事务、国防建设、尖端科学技术领域**的计算机信息系统 |
| **行为** | 违反国家规定，侵入上述系统 |
| **入罪门槛** | **行为犯**，没有"情节严重"的门槛，只要侵入即构成犯罪 |
| **刑罚** | 三年以下有期徒刑或者拘役 |

> ⚠️ **最高检官方解读（2017）**：这是白帽子面临的"**第一条行为红线**"。对于这三类系统，行为人主观意图的善恶不影响定罪。**即使是善意检测，只要侵入了这三类系统，就可能构成犯罪。**

### 2.2 《刑法》第285条第2款——非法获取计算机信息系统数据、非法控制计算机信息系统罪

| 项目 | 内容 |
|------|------|
| **对象** | 第1款规定以外的计算机信息系统 |
| **行为** | 侵入或采用其他技术手段，获取系统中存储/处理/传输的数据，或对系统实施非法控制 |
| **入罪门槛** | **情节犯**，需"**情节严重**"才构成犯罪 |
| **"情节严重"标准** | 见下表 |
| **刑罚（情节严重）** | 三年以下有期徒刑或者拘役，并处或者单处罚金 |
| **刑罚（情节特别严重）** | 三年以上七年以下有期徒刑，并处罚金 |

**"情节严重"的司法解释标准**（两高《关于办理危害计算机信息系统安全刑事案件应用法律若干问题的解释》：

| 情形 | 标准 |
|------|------|
| 获取支付结算、证券交易、期货交易等网络金融服务的身份认证信息 | 10组以上 |
| 获取第(一)项以外的身份认证信息 | 500组以上 |
| 非法控制计算机信息系统 | 20台以上 |
| 违法所得 | 5000元以上 |
| 造成经济损失 | 10000元以上 |
| 其他情节严重的情形 | — |

> ⚠️ **最高检官方解读（2017）**：这是白帽子面临的"**第二条行为红线**"。虽然本罪有"情节严重"门槛，但白帽子在检测过程中获取的数据往往远超漏洞测试的合理范畴，极易突破入罪标准。

### 2.3 《刑法》第285条第3款——提供侵入、非法控制计算机信息系统程序、工具罪

提供专门用于侵入、非法控制计算机信息系统的程序、工具，或者明知他人实施侵入、非法控制行为而为其提供程序、工具的，构成此罪。

> ⚠️ 对于白帽子：**禁止制作、传播或销售任何专门用于渗透的工具**（如漏洞利用框架、自动化扫描工具的破解版等）。

### 2.4 《刑法》第286条——破坏计算机信息系统罪

| 行为类型 | 后果要求 |
|----------|---------|
| 对计算机信息系统功能进行删除、修改、增加、干扰 | 造成系统不能正常运行，后果严重 |
| 对系统中存储/处理/传输的数据和应用程序进行删除、修改、增加 | 后果严重 |
| 故意制作、传播计算机病毒等破坏性程序 | 影响系统正常运行，后果严重 |

> ⚠️ 渗透测试中如果导致目标系统瘫痪、数据损坏或服务中断，可能触发此罪。

### 2.5 其他可能触及的关联罪名

- **侵犯公民个人信息罪**（第253条之一）：获取个人信息超过法定数量
- **侵犯商业秘密罪**（第219条）：获取并泄露测试过程中接触到的商业秘密
- **非法获取国家秘密罪**（第282条）：涉及国家秘密信息

## 3. 补天/漏洞盒子等平台的授权范围

### 3.1 平台授权的本质——"合同授权"的法律效力

补天、漏洞盒子等平台的核心运作模式：**平台与企业签订授权合同 → 平台将授权传导给白帽子 → 白帽子在授权范围内测试。**

**关键法律问题：这种授权能完全免责吗？**

**法学界（中国社科院法学所赵精武）的权威分析指出：**
> 即便测试平台与被测试系统所有者签订挖掘授权合同，仍然存在违法的风险，因为该合同会因触犯《合同法》第五十四条第五款中的"违反法律、行政法规的强制性规定"特殊规定而归于无效。**易言之，无论被测试系统软件所有者是否与平台签订合同，抑或事后是否追认该挖掘行为，均不影响"白帽子"受《刑法》第二百八十五条的规制。**

➡️ **结论：平台授权 ≠ 完全免责。平台授权可以大大降低风险，但不能完全排除刑法第285条的适用风险。** 关键在于**测试行为本身是否构成"非法侵入"**。

### 3.2 公益SRC vs 专属SRC vs 众测项目的授权范围差异

| 类型 | 授权来源 | 风险等级 | 说明 |
|------|---------|---------|------|
| **公益SRC**（补天） | 企业在补天平台注册后默认开放 | ⚠️ 中 | 企业通过注册协议授权白帽子测试其已列明的资产 |
| **专属SRC** | 企业与平台签订专门合同 | ✅ 低 | 授权范围明确，有书面合同 |
| **众测/快测** | 平台定向邀请 + 签署保密协议 | ✅ 最低 | 限定时间、范围、方法，有VPN隔离 |
| **企业自建SRC** | 企业在自己的SRC网站公示规则 | ⚠️ 中 | 需要仔细阅读该企业的SRC规则 |

### 3.3 测试行为何时变为"非法"——关键判断标准

根据CNVD（国家信息安全漏洞共享平台）的《网络安全众测平台白帽用户安全测试行为准则》，合法测试的边界如下：

**当测试行为超出以下"无害化原则"时，即变为非法：**

#### ① 机密性无害化——禁止获取和留存数据

| ✅ 可以做（证明存在即可） | ❌ 不能做（切勿越界） |
|--------------------------|---------------------|
| 证明可非授权访问/越权 | 获取和留存用户信息、文件 |
| 证明可执行数据库查询 | 查询个人信息、业务数据的详细内容 |
| 证明可获得系统高权限 | 获取其他用户数据和业务数据 |
| — | **以当前主机为跳板扫描内网** |

#### ② 可用性无害化——禁止破坏服务

| ✅ 可以做 | ❌ 不能做 |
|---------|----------|
| 轻量级扫描 | 大流量、大规模扫描（可能导致瘫痪） |
| 单点测试 | **DoS/DDoS测试** |
| — | 可能导致业务逻辑紊乱或用户经济损失的操作 |

#### ③ 完整性无害化——禁止篡改数据

| ✅ 可以做 | ❌ 不能做 |
|---------|----------|
| 证明可获得后台操作权限 | 实际执行编辑、增删、篡改操作 |
| 证明可获得数据高权限 | 执行文件/程序/数据的编辑、增删、篡改 |
| 证明可上传可执行文件 | **驻留带有控制性目的的程序/代码**（如留后门、WebShell） |

### 3.4 补天平台的具体协议要点

> 来源：补天众测帮助文档 + 漏洞盒子白帽子注册协议

- 补天众测是**"在得到企业授权的前提下"**进行的安全测试
- 众测项目通过实名认证、**双因子认证、网络监管**等安全手段管控
- **必须签署保密协议**后才能参与
- 通过平台发放的**VPN**进行测试
- **不得私自联系厂商**
- 漏洞修复前**不得对外公开**

### 3.5 漏洞盒子白帽子协议关键条款

> 来源：vulbox.com/agreement

协议第9.3条明确禁止的行为：
> - 未经允许，进入计算机信息网络或者使用计算机信息网络资源
> - 未经允许，对计算机信息网络功能进行删除、修改或者增加
> - 测试行为造成了对机构的攻击行为，包括但不限于**数据泄露、数据丢失、服务异常、访问缓慢**等
> - 测试行为造成了对机构的声誉影响，包括但不限于**曝光机构漏洞、勒索机构、倒卖机构数据**等
> - 测试行为造成了对机构的事实性损害，包括但不限于**经济损失、名誉损害**等
> - 不得实施**非法侵入、干扰、破坏关键信息基础设施**的活动

关键是协议中明确写了一条风险隔离条款：
> "对于用户在VULBOX上提交与发布的漏洞，**用户需要保证获取及研究漏洞的方法、方式、工具及手段的合法性**，VULBOX对此不承担任何法律责任。"

➡️ **这意味着：平台不兜底，白帽子自行承担行为合法性责任。**

## 4. 绝对禁止的操作红线

综合《网络安全法》《刑法》、CNVD准则、各平台协议，以下操作属于**绝对禁止**：

### 🔴 红线一：涉国家/国防/尖端科技系统
**绝对不可碰。** 国家事务、国防建设、尖端科学技术领域的计算机信息系统，任何未经授权的侵入即构成犯罪，主观善意不能免责。

### 🔴 红线二：关键信息基础设施（CII）
《关键信息基础设施安全保护条例》第43条：非法侵入、干扰、破坏关键信息基础设施，尚不构成犯罪的，由公安机关没收违法所得，处5日以下拘留。

### 🔴 红线三：数据越界获取
**"证明存在"不等于"可以下载"。** 发现SQL注入 → 用`1=1`证明可注入即可，禁止`SELECT * FROM users` 拖库。

### 🔴 红线四：DoS/DDoS测试
绝对不能进行拒绝服务攻击测试。这是破坏计算机信息系统罪的典型行为。

### 🔴 红线五：留后门/WebShell/Trojan
任何形式的后门驻留、权限维持、远程控制植入都是刑事犯罪。

### 🔴 红线六：数据篡改与破坏
不能删除、修改、增加目标系统中的数据和应用。CNVD准则明确：获得高权限后，不应再执行文件/程序/数据的编辑、增删、篡改。

### 🔴 红线七：以跳板扫描内网
不能以测试目标主机作为跳板，扫描其内部网络的其他系统。这让攻击范围从单个系统扩大到整个网络。

### 🔴 红线八：公开发布未修复漏洞
《网络安全法》第28条：向社会发布系统漏洞，应当遵守国家有关规定。漏洞未修复前不得公开。

### 🔴 红线九：利用社会工程学攻击内部人员
不得对目标企业的员工进行钓鱼、诈骗、社工测试，除非有明确书面授权。

### 🔴 红线十：倒卖漏洞和数据
这是严重刑事犯罪，涉及多个罪名。

## 5. 真实案例：白帽子踩线被追责

### 案例一：袁炜案（乌云平台）——白帽子被抓第一案

| 项目 | 内容 |
|------|------|
| **时间** | 2015年12月检测 → 2016年1月报案 → 2016年3月刑拘 |
| **平台** | 乌云（现已关闭） |
| **目标** | 世纪佳缘网站 |
| **操作** | 使用SQL注入工具对世纪佳缘进行检测，**通过SQL注入请求了4400余条数据** |
| **后果** | 世纪佳缘报警称900多条有效数据被非法获取 |
| **罪名** | 涉嫌非法获取计算机信息系统数据罪 |
| **经过** | 2016年3月8日刑事拘留 → 4月12日批捕 → 审查起诉 |
| **行业影响** | 乌云平台随后关闭，引发全行业对白帽子法律风险的关注 |

**反思**：袁炜案的关键争议点——他是在乌云注册仅2个月的实习白帽子，测试时尚未获得世纪佳缘的授权。他在检测过程中**实际下载了用户数据**，这是他从"善意检测"滑入"非法获取"的关键一步。

💡 **教训**：**证明漏洞存在 ≠ 下载数据。** 在证明存在SQL注入漏洞时，只需要证明"可以查询到数据"即可，不需要实际下载大量用户记录。

### 案例二：百度文库爬虫案（2017）

| 项目 | 内容 |
|------|------|
| **行为人** | 白帽子利用爬虫大量抓取百度文库文档 |
| **结果** | 被以非法获取计算机信息系统数据罪追诉 |
| **关键点** | 爬虫突破了百度文库的反爬措施，获取了付费文档 |

💡 **教训**：即使数据在"公网上"，通过技术手段突破网站的安全防护措施获取数据，仍然可能构成犯罪。

### 案例三：某白帽子渗透测试"顺手拖库"案

| 项目 | 内容 |
|------|------|
| **操作** | 在某SRC测试中发现SQL注入，本应仅证明即可，但下载了整个用户表 |
| **结果** | 被目标企业报警处理 |
| **后续** | 与企业达成和解，但已造成法律风险 |

💡 **教训**：**测试过程中留下的操作日志是呈堂证供。** 企业安全团队会排查所有访问记录。

### 案例四：马某某等"某索云盘搜索"插件案

**（人民法院案例库入库编号：2024-04-1-252-002）**

| 项目 | 内容 |
|------|------|
| **操作** | 开发浏览器插件，在用户不知情且未获授权情况下，抓取用户百度网盘分享链接的地址和提取码 |
| **罪名** | 非法获取计算机信息系统数据罪 |
| **刑罚** | 马某某：有期徒刑3年缓刑4年，罚金1万元 |
| **违法所得** | 7万余元 |

💡 **教训**：**未经授权自动抓取其他平台数据并用于牟利，即使是"技术中性"的工具，只要实质是非法获取数据，就是犯罪。**

### 案例五：指导案例145号——张竣杰等非法控制计算机信息系统案

| 项目 | 内容 |
|------|------|
| **操作** | 对存在防护漏洞的目标服务器植入木马程序，获取后台操作权限，上传赌博广告页面 |
| **控制数量** | 113台服务器 |
| **一审罪名** | 破坏计算机信息系统罪 |
| **二审改判** | 非法控制计算机信息系统罪 |

## 6. 关于第三方服务的测试风险

### 6.1 问题场景

在SRC挖洞中，经常遇到这种情况：
> 目标企业（如某电商）的网站上使用了第三方服务（如某CDN、某支付网关、某SaaS客服系统）。白帽子在测试时，发现**第三方服务本身存在漏洞**（如该CDN厂商的某个接口存在越权）。

**问题：白帽子能否测试该第三方服务？授权是否覆盖？**

### 6.2 法律风险分析

| 情形 | 授权来自 | 风险 |
|------|---------|------|
| 第三方服务是目标企业的**子域名/自部署实例**（如 `chat.target.com`） | ✅ 目标企业SRC的授权通常覆盖其自有资产 | ⚠️ 低~中 |
| 第三方服务是独立的SaaS（如 `vendor.com`），仅被目标企业**嵌入使用** | ❌ 授权不覆盖第三方厂商的系统 | 🔴 **高** |
| 测试**从目标网站出发，利用了第三方服务的漏洞来攻击目标自身**（如通过XSS获取目标的管理员Cookie） | ✅ 目标在授权范围内 | ⚠️ 中 |
| 测试**深入第三方服务的内部系统**（如注册第三方厂商的测试账号，测试其后台） | ❌ 完全无授权 | 🔴 **极高** |

### 6.3 关键判断标准

**判断标准：你的测试行为是否侵入了一个你没有获得授权的计算机信息系统？**

- 如果你测试的是**的目标网站的某个功能**，该功能恰好由第三方提供——✅ 通常被授权覆盖
- 如果你**直接攻击第三方厂商的基础设施**——❌ 不在授权范围内
- 如果你在测试中**发现了第三方服务的0day**——❌ 不能以目标SRC的授权作为测试第三方的合法依据

### 6.4 典型案例——爬虫抓取第三方数据

在《人民法院案例库 2024-04-1-252-002》中，被告人开发的插件抓取了百度网盘的数据，虽然用户是百度网盘的合法使用者，但**未经百度授权自动抓取其数据**被认定为犯罪。

➡️ **推论：即使你是目标SRC的授权测试者，也不代表你可以自动获得目标使用的第三方服务的测试授权。**

### 6.5 安全做法

1. **只测试目标企业的自有资产**（IP/域名在SRC公告的资产范围内）
2. 发现第三方服务漏洞时，**通过目标企业SRC渠道报告，说明这是第三方组件的问题**
3. **不要直接去测试第三方厂商的系统**——那属于另一个授权范围
4. 如果第三方是开源组件，可以**在本地搭建测试环境复现**，不涉及网络侵入

## 7. 如何合法保护自己（证据保全与合规流程）

### 7.1 测试前必须完成的事项

#### ✅ 确认授权链

```
目标企业 → 与平台签订授权合同 → 平台 → 授权给白帽子 → 你
```

- **在SRC平台测试**：确认目标企业在平台上有有效的资产授权声明
- **在企业自建SRC测试**：仔细阅读该企业的SRC规则和授权范围
- **在众测项目测试**：确认签署了保密协议，收到VPN和测试范围

#### ✅ 记录授权证据

保存以下文件的截图/PDF：
- SRC平台的授权声明页面
- 企业SRC规则中列明的测试范围（IP段/域名列表）
- 参与众测的项目范围和期限说明
- 保密协议签署记录

#### ✅ 确定测试范围

精确记录：
- 允许测试的**域名列表**
- 允许测试的**IP段**
- 允许测试的**时间段**
- **明确禁止测试的内容**（如生产数据库、用户个人信息等）

### 7.2 测试中的操作规范

#### ✅ 证据保存清单

| 需要保存的证据 | 保存方式 |
|---------------|---------|
| 漏洞验证过程截图（带时间戳） | 本地加密存档 + 云备份 |
| 测试工具的访问日志 | 保存完整日志 |
| Burp Suite/抓包工具的请求记录 | 导出为文件 |
| 发现漏洞的时间线记录 | 文档记录 |
| 与平台的沟通记录 | 邮件/站内信截图 |
| 测试环境的配置信息 | 记录版本、参数 |

#### ✅ 核心合规操作指南

1. **最小必要原则**：只获取必要的最小量数据来证明漏洞存在
2. **即时销毁**：验证完成后立即删除获取的测试数据
3. **先证明再深入**：先证明漏洞存在，有需要再申请深入测试
4. **通过正规渠道提交**：只通过SRC/平台官方渠道提交漏洞
5. **不私下联系厂商**：违反平台规则，也可能导致证据链不完整
6. **不在公网讨论未修复漏洞**：违反《网络安全法》第28条
7. **不使用非法工具**：不使用破解版、后门版测试工具

### 7.3 漏洞提交后的注意事项

#### ✅ 提交报告时的证据链

提交漏洞报告时，应包含（但不越界）：
- 漏洞类型、影响范围
- 复现步骤（详细的技术描述）
- 漏洞证明（截图/PoC）
- 修复建议
- **不要包含完整的数据集**——只提供样本证明即可

#### ✅ 当前法律环境的重要变化

**2025年《网络犯罪防治法（征求意见稿）》** 第25条提出：

> 未经省级以上网信部门、公安机关批准或者行业主管部门、运营者授权，**任何个人、组织不得对网络安全等级保护第三级（含）以上的网络开展网络安全漏洞探测、渗透性测试等可能影响网络安全的活动。**
>
> 未经设区的市级以上网信部门、公安机关批准或者行业主管部门、运营者授权，**任何个人、组织不得对网络安全等级保护第二级（含）以下的网络开展网络安全漏洞探测、渗透性测试等可能影响网络安全的活动。**

⚠️ **这条规定一旦正式生效，意味着：**
- 对等保三级及以上系统（通常是大型企业、政府、金融、医疗等）进行渗透测试，**除了运营者授权外，可能还需要政府部门批准**
- **未经授权的漏洞探测行为本身就可能违法**，而不仅仅是在获取数据后才违法

### 7.4 如果收到"律师函"或警方联系

1. **立即停止所有测试活动**
2. **保存所有测试记录和授权证明**
3. **不要删除任何数据**（删除可能被视为销毁证据）
4. **不要私自与对方沟通**（言论可能被用作不利证据）
5. **尽快联系律师**（选择有网络安全刑事案件经验的律师）
6. **通过平台方协调**（如果是平台项目，平台有协调义务）

## 8. 核心结论

### 8.1 一句话总结

> **在白帽子法律风险上，中国的法律环境是："合同授权"是必要条件但不是充分条件，平台授权可以大幅降低风险但不能完全免责，真正决定合法与非法的分界线是你的测试行为是否构成"非法侵入"。**

### 8.2 安全测试的"三不"原则

| 原则 | 含义 |
|------|------|
| **不越权** | 只在SRC/平台明确授权的资产范围内测试 |
| **不拿数** | 证明漏洞存在即可，绝不下载用户数据 |
| **不搞瘫** | 绝不进行任何可能导致服务中断的测试 |

### 8.3 法律风险从低到高的测试类型

```
众测项目（有合同+有VPN+有时限） → 低风险
专属SRC（有合同授权） → 中低风险
公益SRC（平台注册授权） → 中风险
企业自建SRC（需仔细读规则） → 中风险
自行测试无授权系统 → 高风险（可能刑事犯罪）
测试关键信息基础设施 → 极高风险
测试涉国家/国防/尖端科技系统 → 极其严重（行为犯，主观善意不免责）
```

### 8.4 推荐的安全实践路径

```
① 仅在SRC平台/企业授权的范围内测试
② 仔细阅读并截图保存授权范围
③ 测试中严守"最小必要"原则
④ 验证完成后立即清除测试数据
⑤ 通过官方渠道提交漏洞
⑥ 不公开、不传播未修复漏洞
⑦ 定期学习最新法律法规变化
```
