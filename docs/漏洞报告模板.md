# 漏洞报告模板

## 提交前检查清单

- [ ] 7-Question Gate 全部PASS
- [ ] 不在永不提交清单上
- [ ] 请求包完整（含Header）
- [ ] 响应包完整（含数据）
- [ ] PII已脱敏（手机号、身份证）
- [ ] Cookie/Token已脱敏
- [ ] 复现步骤可复现
- [ ] 影响量化有数字
- [ ] Critical/High：两个独立工具复现
- [ ] 标题用了精确端点
- [ ] 没有"could potentially"等模糊用语

---

## 报告模板（漏洞盒子/补天）

```markdown
# [漏洞类型] in [精确端点] allows [角色] to [影响]

## 漏洞概述
[一段话：什么漏洞、在哪、攻击者能做什么。第一句=影响]

## 漏洞详情
**漏洞类型**: [IDOR/XSS/SQLi/信息泄露/认证绕过/...]
**影响端点**: [精确URL]
**影响版本**: [如有]

## 复现步骤
**环境**:
- 攻击者账号: [attacker@test.com, user_id = 123]
- 受害者账号: [victim@test.com, user_id = 456]
- 目标: [https://target.com]

**步骤**:
1. [第一步操作]
2. 发送以下请求：
```http
[精确HTTP请求]
```
3. 观察响应：
```json
[响应数据]
```

## 影响
[数据影响 + 业务影响 + 影响范围]

## 修复建议
[具体修复方案，代码级]
```

---

## 标题公式

```
[漏洞类型] in [精确端点/功能] allows [攻击者角色] to [影响] [受害者范围]
```

### 好标题
- `IDOR in /api/v2/invoices/{id} allows authenticated user to read any customer's invoice data`
- `Missing auth on POST /api/admin/users allows unauthenticated attacker to create admin accounts`
- `Stored XSS in profile bio field executes in admin panel — allows privilege escalation`
- `SSRF via image import URL parameter reaches AWS EC2 metadata service`

### 坏标题
- `IDOR vulnerability found`
- `Broken access control`
- `XSS in user input`
- `Security issue in API`

## PII脱敏清单

| 数据类型 | 脱敏方式 | 示例 |
|---|---|---|
| 手机号 | 保留前3后4 | 138****1234 |
| 身份证 | 保留前3后4 | 110***********1234 |
| 邮箱 | 保留首字母和域名 | t***@test.com |
| 银行卡 | 保留后4位 | ************1234 |
| 姓名 | 保留姓 | 张** |
| 地址 | 保留省市 | 北京市朝阳区*** |
| Cookie/Token | 截断 | eyJhbGc...（前20字符）|
| 密码 | 完全隐藏 | ****** |

## 报告语气规则

### 永远不要用
- "could potentially"
- "could be used to"
- "may allow"
- "it is possible that"

### 永远要用
- "An attacker can..."
- "I confirmed this by..."
- "The response contains..."
- "This allows..."
