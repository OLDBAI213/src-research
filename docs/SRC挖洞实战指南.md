# SRC挖洞实战指南：补天(butian.net) & 漏洞盒子(vulbox.com)

> 研究日期：2026-05-19 | 来源：官方文档 + 社区经验 + 白帽分享
> 适用对象：从零开始的SRC漏洞挖掘新手

## 一、补天平台（butian.net）详解

### 1.1 平台概述

补天漏洞响应平台，由奇安信集团运营（原360旗下），2013年上线。是国内最大的第三方漏洞响应平台之一，被公安部、工信部、CNCERT、国测等机构评定为优秀技术支撑单位。

补天有三种业务模式：

| 模式 | 说明 | 奖励来源 | 适合谁 |
|------|------|----------|--------|
| **公益SRC** | 白帽子随机发现漏洞提交，平台审核后通知厂商认领 | 补天平台承担（库币KB） | **新人首选，练手** |
| **专属SRC** | 企业入驻补天建立专属SRC，发布测试计划征集漏洞 | 厂商自定现金奖励 | 有经验的白帽子 |
| **补天众测** | 定向邀请精英白帽做渗透测试，需邀请码 | 项目制高收益 | 高级白帽子（需邀请码） |

### 1.2 注册与认证流程

**第1步：官网注册**
- 访问 https://www.butian.net/Register.html
- 填写手机号/邮箱、设置密码、完成验证码

**第2步：实名认证（必须做，否则无法提交漏洞）**
- 在个人中心上传身份证正反面照片
- 审核一般1-2个工作日通过
- ⚠️ 不认证连漏洞都提交不了——这是新手最常见卡住的地方

**第3步：完善个人资料**
- 填写擅长领域（Web安全/移动安全/二进制等）
- 绑定微信服务号（可实时接收漏洞进度通知）
- 填写银行卡信息（用于现金提现）

**第4步（进阶）：申请众测资格**
- 满足以下条件**至少2条**，联系补天运营「荷兰豆」QQ: 2656450853
- 条件：①有CTF获奖经历 ②有知名CVE/CNVD编号 ③有公开发表的漏洞分析文章 ④补天排行榜前100 ⑤有安全行业从业证明
- 审核通过后签署保密协议，获取唯一邀请码

### 1.3 漏洞类型与收录范围

补天接受两大类漏洞：

**① 通用漏洞**（奖励更高）
- 第三方软件/应用/系统的漏洞，如ECShop、Discuz、PHPCMS的SQL注入、XSS等
- 开源软件、安全浏览器、手机App、路由器固件、开发框架
- VPN系统、防火墙系统等安全产品本身的漏洞

**② 事件漏洞**（非通用型）
- 具体网站/应用的漏洞：如xx网站命令执行、xx电商订单泄露可任意充值
- 这类漏洞按厂商规模分级定价

**收录范围**：专属SRC + 公益SRC + 未注册厂商的漏洞

### 1.4 奖励机制（核心）

#### 事件漏洞奖励标准

| 漏洞等级 | 小型厂商 | 中型厂商 | 大型厂商 |
|---------|---------|---------|---------|
| 低危 | 1-3 KB | 2-6 KB | 3-10 KB |
| 中危 | 2-5 KB | 3-12 KB | 10-30 KB 或 ¥100-500 |
| 高危 | 4-20 KB 或 ¥100-200 | 6-25 KB 或 ¥100-1000 | ¥100-2000 |

#### 通用漏洞奖励标准

| 等级 | 奖励范围 |
|------|---------|
| 低危 | ¥200-¥800 |
| 中危 | ¥800-¥3,000 |
| 高危 | ¥3,000-¥10,000 |

#### 奖励形式

- **库币（KB）**：补天虚拟积分，1KB ≈ 1元人民币（可在商城兑换或提现）
- **荣誉币（RYB）**：特定厂商漏洞发放，可兑换为KB
- **现金**：银行汇款，每周三支付（法定节假日顺延），支付后48小时内到账
- **积分**：中危1KB=2积分，高危1KB=4积分（积分用于排名）

#### 排行榜奖励
- 月度荣誉榜：荣耀个人/团队/跃秀新星，上榜有额外奖金
- 风云榜：积分/赏金/有效率排名
- 降级奖励的漏洞不降积分（即中危仍按中危算积分）

### 1.5 漏洞提交模板

补天官方提供了提交模板（https://butian.net/Article/content/id/543），核心结构：

```
【漏洞标题】：[厂商/产品名] + [URL/模块] + [漏洞类型]
  例：xx商城订单系统SQL注入漏洞

【漏洞类型】：SQL注入/XSS/命令执行/越权/逻辑漏洞等

【漏洞等级】：严重/高危/中危/低危

【漏洞描述】：
- 漏洞所在的业务模块和功能点
- 触发漏洞的条件和前置要求
- 可能造成的安全影响

【复现步骤】（最重要）：
1. 访问 http://xxx.com/login
2. 在用户名输入框中输入 Payload: XXX
3. 抓包查看返回数据
4. 得到管理员密码Hash（见截图）

【漏洞证明】（必须有）：
- 至少2-3张清晰截图（关键步骤+最终效果）
- Payload或关键请求数据
- 证明漏洞确实存在的证据（泄露的数据、执行结果等）

【修复建议】：
- 针对性地给出1条以上修复方案
```

### 1.6 审核流程与时间线

```
提交漏洞 → 平台审核(1个工作日) → 审核通过 ↓
                                    ↓ 审核不通过 → 查看驳回原因修改
厂商认领(7天内) → 厂商复审(1周内)
    ↓                        ↓
无人认领(7天后自动确认)   厂商超时(自动判定通过)
    ↓                        ↓
奖金确认 → 7个工作日内到账
```

**关键时间节点**：
- 平台初审：约1个工作日
- 厂商认领等待期：最长7天（厂商不认领则自动确认）
- 厂商复审：约1周（超时自动通过）
- 奖金到账：确认后7个工作日左右
- 现金发放：每周三银行汇款

**漏洞状态解读**：
- 待审核 → 审核中 → 审核完成（等待厂商认领）→ 厂商确认 → 已修复/已关闭

### 1.7 常见驳回原因及应对

| 驳回原因 | 分析 | 应对策略 |
|---------|------|---------|
| **漏洞无法复现** | 复现步骤不清晰，缺少关键参数 | 补充完整Payload和URL，重新截图，写清每一步操作 |
| **漏洞已被重复提交** | 别人先提交了 | 搜一下再提交，加快速度；或者换个角度利用 |
| **厂商权重过低/无法联系** | 太小、已停止维护的厂商 | 优先挖公益SRC中活跃厂商的漏洞 |
| **报告不规范** | 截图模糊、描述不清、无危害证明 | 严格按照官方模板编写 |
| **漏洞危害不足** | 漏洞确实存在但危害太小 | 尝试找更深层的利用方式，或者换个目标 |
| **测试范围越界** | 测试到未授权的资产 | 只测目标范围内的资产 |

### 1.8 白帽子信誉机制

- 初始信誉值：100
- 刷洞/一洞多投/抄袭：扣10信誉值（专属SRC扣20）
- 辱骂审核人员/不良言论：酌情扣分
- 信誉值 ≤ 60：封号处理
- 一个月无违规且提交过有效漏洞：+1信誉值

### 1.9 不收录/不接受的漏洞类型

根据补天行为规范和行业惯例，以下通常不收录：
- 自XSS（Self-XSS）
- 无敏感操作的CSRF（如收藏、取消收藏）
- URL跳转（需要复杂交互的）
- 服务器信息泄露（如phpinfo）
- 内网IP/域名泄露
- 无意义的源码泄露
- 纯扫描器报告（无手动验证）
- 已公开的漏洞（厂商已发布补丁后的）

## 二、漏洞盒子（vulbox.com）详解

### 2.1 平台概述

漏洞盒子（Vulbox）隶属于上海斗象信息科技有限公司（也是知名安全媒体FreeBuf的运营方），是国内领先的安全众测平台之一。采用PTaaS（渗透测试即服务）模式，连接企业和白帽子安全专家。

### 2.2 注册与认证流程

**第1步：账号注册**
- 访问 https://www.vulbox.com 注册
- 填写邮箱/手机号、设置密码

**第2步：实名认证**
- 必须完成实名认证才能成为正式用户
- 未认证用户只能享有部分功能
- 认证后才有权限提交漏洞和获取奖励

**第3步：完善支付信息**
- 绑定银行卡/支付宝信息
- 用于现金奖励提现

**第4步：报名众测项目**
- 在项目大厅查看可参与的任务
- 部分项目需要报名审核，审核通过后才能提交漏洞
- 每个项目都有特定的资产范围和测试规则

### 2.3 漏洞处理流程

```
提交漏洞 → 待审阅 → 企业审核(1工作日内预审)
                              ↓
                      审核不通过 → 忽略/要求补充
                              ↓
                      审核通过 → 待确认(3工作日内)
                              ↓
                      漏洞确认 → 待修复
                              ↓
                      企业修复完成 → 漏洞关闭
```

**关键规则**：
- 漏洞一旦提交**无法编辑修改**，只能评论补充——提交前务必检查清楚
- 同一时间段内重复漏洞：**以第一份最完整报告为准**
- 不同时间段重复漏洞：**以第一个提交为准**
- 前后关联漏洞合并处理（如先提交弱口令进入后台，后提交的SQL注入合并处理）

### 2.4 报告格式要求

漏洞盒子对报告有明确的质量要求，影响最终奖励：

**报告质量维度**：
- **有效性**：漏洞是否真实存在
- **漏洞等级**：严重(高危)/中危/低危 —— 基于CVSS评分标准
- **报告质量**：优秀/良好/差

**高质量报告要素**：
1. **标题**：明确漏洞影响的域名/产品名称 + 漏洞类型
2. **漏洞描述**：详细的漏洞描述，涉及的URL、参数等
3. **漏洞证明**：至少2-3张截图 + 影响说明
4. **复现步骤**：清晰的、可复现的操作流程
5. **修复建议**：至少一条可执行的修复方案
6. **PoC**：完整的利用代码或关键请求数据

### 2.5 奖励机制

#### 奖励形式
- **现金奖励**：完善支付信息后可申请提现
  - 申请后**下个月10日-15日**以银行转账形式发放
  - 按照税务规定预扣个人所得税（"连续劳务所得"）
- **金币奖励**：虚拟积分
- **荣誉奖励**：排行榜、称号等

#### 奖励影响因素
奖励金额由三个维度加权计算：
```
奖励 = f(业务类型, 项目级别, 漏洞等级, 报告质量)
```

具体来说：
- 业务类型的资产重要性越高 → 奖励越高
- 项目级别越高 → 奖励越高
- 漏洞等级越高 → 奖励越高
- 报告质量越高（优秀 > 良好 > 差）→ 奖励越高

#### 赛季积分系统
漏洞盒子有赛季排名机制：
- 赛季积分需≥500分才可进入新秀榜
- 新秀榜限制：赛季开始前没有提交过任何有效漏洞（公益除外）
- 积分由"有效性 + 漏洞等级 + 报告质量"三维度复合计算

### 2.6 漏洞等级分类

漏洞盒子采用CVSS标准进行评分，等级分类：

| 等级 | 典型漏洞示例 |
|------|------------|
| **严重/高危** | 远程命令执行、SQL注入(核心DB)、上传Webshell、批量越权获取用户数据 |
| **中危** | 存储型XSS、任意文件操作、普通越权、CSRF(涉及资金/密码) |
| **低危** | 反射型XSS、路径泄露、SVN信息泄露、phpinfo |

### 2.7 常见驳回/忽略原因

- 漏洞无法复现（报告质量差）
- 重复漏洞（别人先提交了）
- **弱口令问题**：同一系统多个用户弱口令只确认第一个；同一用户弱口令登录不同系统算同一漏洞
- 关联漏洞合并处理（如通过弱口令进入后台后发现的漏洞）
- 不涉及安全问题的Bug（产品功能缺陷、样式问题等）
- 利用条件过于苛刻的漏洞
- 无敏感信息的泄露
- 测试行为造成实际损害（数据泄露、服务异常等）

### 2.8 白帽子行为规范（红线）

违反以下规定会被封号甚至追究法律责任：
- 测试行为造成机构攻击（数据泄露、数据丢失、服务异常）
- 测试行为造成机构声誉影响（曝光漏洞、勒索、倒卖数据）
- 测试行为造成机构事实性损害（经济损失、名誉损害）
- 未经允许公开已提交漏洞（包括已忽略漏洞）
- 未经授权测试关键信息基础设施

## 四、实战策略与经验总结

### 4.1 新人成长路线

```
阶段1️⃣：补天公益SRC练手
  → 找权重大、活跃的厂商
  → 以SQL注入、XSS、逻辑漏洞入手
  → 不追求高赏金，追求"第一个有效漏洞"

阶段2️⃣：补天专属SRC挖现金
  → 积累一定经验后转专属SRC
  → 关注项目大厅，报名有现金奖励的项目
  → 重点挖逻辑漏洞、越权、支付漏洞

阶段3️⃣：漏洞盒子项目制
  → 在补天积累经验后，转漏洞盒子报名众测项目
  → 可以同时两个平台跑

阶段4️⃣：各大互联网SRC
  → 能在补天专属SRC挖洞，基本可以去各大小厂SRC
  → 阿里、腾讯、字节、小米等
```

### 4.2 挖洞效率技巧

1. **信息收集是基础**：子域名收集（OneForAll/subfinder）、端口扫描、指纹识别
2. **优先挖逻辑漏洞**：逻辑漏洞（越权、支付篡改、验证码绕过）往往比技术型漏洞更容易找到、收益更高
3. **盯紧更新**：厂商新上线功能、新漏洞披露（如Log4j）、新框架发布后是挖洞黄金期
4. **一个点深入挖掘**：找到一个漏洞不要急着交，看看能不能连锁利用（如弱口令→后台→上传→RCE）
5. **多关注厂商公告**：补天有活动中心，参与活动有额外加成奖励
6. **分散目标**：不要只盯着一个大厂，多个厂商同时跑，提高中洞概率

### 4.3 报告编写黄金法则

1. **截图必须清晰**：包含URL栏 + 关键数据 + 最终效果，不要马赛克关键信息
2. **复现步骤要"傻瓜式"**：审核人员要能按你的步骤一步步复现才算通过
3. **危害证明要有力**：比复现步骤更能说服审核——泄露了什么数据、能控制什么
4. **不要只交扫描器报告**：手动验证是必须的
5. **多个洞源合并提交**：同一漏洞源的多个问题合并到一份报告中（避免被认为是重复）
6. **提交前搜索查重**：看看平台上有没有类似的已提交漏洞

### 4.4 注意事项与红线

- **绝对不要**测试未授权的资产
- **绝对不要**在测试中泄露或倒卖数据
- **绝对不要**公开已提交的漏洞细节（包括已忽略的）
- **绝对不要**一洞多投（补天扣信誉值，严重封号）
- **不要**辱骂审核人员或在社群发表不良言论
- 测试过程中发现敏感数据，立即停止并联系平台
- 漏洞提交后耐心等待，不要频繁催促审核
- 被驳回也别灰心，看驳回原因修改后重新提交
