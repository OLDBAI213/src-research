## 1. SRC报告被拒的十大原因（含真实案例）

### 🔴 原因一：漏洞无法复现（最常见的拒绝原因）

**审核反馈**："经测试无法复现，请补充详细步骤。"

**失败案例**：某新手提交了一个"SQL注入漏洞"，只写了"在参数id处加单引号报错"，但没有提供完整的请求包、注入语句类型和数据库版本信息。审核尝试后未复现，直接忽略。

**根因分析**：
- 报告写得太简略，缺少关键数据包
- 测试环境依赖特定条件（如特定Cookie、特定时间窗口）
- 漏洞是"偶然触发的"而非稳定复现的
- 使用了自动化扫描工具的原始输出，未人工验证

**✅ 正确做法**：
```
1. 每个漏洞必须手工复现至少3次，确认稳定
2. 报告中提供完整的HTTP请求/响应数据包
3. 清晰标注测试账号、测试环境、测试步骤
4. Burp Suite截图要有"复现成功的证据"（如回显数据）
```

---

### 🔴 原因二：漏洞被判定为重复提交

**审核反馈**："已有人提交过相同漏洞，按先到先得原则忽略。"

**失败案例**：某新人花了两天时间挖到一个后台弱口令漏洞，兴冲冲提交，结果被告知"该资产已于3天前由其他白帽子提交，被判定为重复漏洞"。

**根因分析**：
- 热门SRC（如腾讯、阿里、字节）的资产被大量白帽子同时测试
- 同一个漏洞由A先提交后，B再提交相同接口的同类问题
- 没有在提交前充分搜索平台的历史漏洞

**✅ 正确做法**：
- 提交前先在平台搜索相似关键词
- 优先挖掘冷门资产（子公司、边缘业务、老系统）
- 同一个漏洞源导致的多个同类问题算一个漏洞（如整站框架漏洞）
- "[同源漏洞]已修复漏洞的绕过方式按原漏洞奖励75%计分"

---

### 🔴 原因三：危害不足/无实际影响（被降级为忽略）

**审核反馈**："该漏洞无实际危害，不予收录。"

**真实案例**：
- 提交"某页面存在Self-XSS（只能攻击自己）"→ 拒绝
- 提交"反射型XSS"在只收存储型XSS的SRC → 拒绝
- 提交"无意义的API Key泄露"（已过期/无权限）→ 拒绝
- 提交"内网IP/域名泄露"没有配合其他漏洞 → 拒绝

**各大SRC明确列出的"忽略"类型**：
> 来源：TSRC、BILISRC、58SRC、猎聘SRC、看云SRC评分标准

| 忽略类型 | 说明 |
|---------|------|
| Self-XSS | 只能攻击自己的XSS |
| 无敏感操作的CSRF | 收藏、点赞、关注等非关键操作 |
| 无意义并发问题 | 浏览量、点赞数、报名人数等 |
| 内网IP/域名泄露 | 无进一步利用证明 |
| 无意义的源码泄露 | .idea、.vscode文件夹等 |
| 401基础认证钓鱼 | 无实际危害 |
| PDF XSS | 影响面极小 |
| 邮箱轰炸 | 多数平台已停止收录 |
| 用户名遍历 | 无敏感信息导出 |
| 仅提供dnslog的log4j2 | "只提供dnslog的'log4j2命令执行漏洞'" |

---

### 🔴 原因四：报告质量差/排版混乱

**审核反馈**："报告过于简单，无法根据报告内容复现，请改进。"

**BILISRC明确写明的拒绝条件**：
> "提交的报告书写过于简单（如报告未指明业务路径、未证明漏洞危害），无法根据报告内容复现，包括但不限于和漏洞审核员反复沟通均无法复现的漏洞。"

**常见问题**：
- 只贴图不写字，审核看不懂图片含义
- 没有标注关键参数/接口
- 缺少测试账号信息（越权类漏洞尤其需要）
- 没有说明漏洞影响范围和危害
- 排版混乱，图片模糊

---

### 🔴 原因五：超出测试范围/违规测试

**审核反馈**："该资产不在收录范围内"或"测试行为违规，账号封禁。"

**真实案例**：
- 某新人挖到一个第三方外包系统漏洞，提交后被告知"外包合作类业务不收录"（58SRC明确规则）
- 某白帽子测试时使用了高危Payload（如拖取数据、删除文件），被SRC永久封号
- 用重型扫描器（AWVS）扫某SRC资产，IP被封，账号被禁

**规则要点**：
> 58SRC:"外包合作类业务：跟58为合作关系或58不负责其安全运营的业务，如：爱房、58天鹅到家、伯小乐。如对58没有直接影响则不收录。"

> 猎聘SRC:"禁止对猎聘客户信息、公司数据、程序代码进行篡改、删除或泄漏操作；禁止使用任何手段发起网络拒绝服务攻击。"

---

### 🔴 原因六：漏洞被判定为"已知"或"正在修复"

**审核反馈**："该漏洞已在排查/修复中，不计分。"

**真实场景**：
- 业务方正在做安全专项治理（如统一排查SQL注入），这时候提交的同类问题不会额外计分
- 同类漏洞在同一个系统里已收录了前2个，后续的被视为同源漏洞

**58SRC规则**：
> "同一二级域名下的越权、SQL注入漏洞，按照漏洞类型分别对最先提交的2个漏洞正常收录和评分，后续相同类型报告视为同源。"

---

### 🔴 原因七：报告内容"证据不足/猜测为主"

**审核反馈**："仅提供理论推测，无实际利用证明。"

**真实案例**：
- "我觉得这个接口可能存在注入点"→ 没有实际测试 → 拒绝
- 只贴了dnslog回显，没有证明能真正执行命令 → 降级
- "这个API Key可能有用"→ 没有验证可调用什么接口 → 拒绝

**TSRC明确拒绝**：
> "无任何证据的猜测，包括但不限于自己QQ被盗就表示有漏洞。"

---

### 🔴 原因八：漏洞价值被判定为"非安全问题/Bug"

**审核反馈**："这是功能Bug，非安全漏洞，不予收录。"

**常见混淆点**：
- 网页样式错乱 → 前端Bug，不是安全漏洞
- 某功能无法使用 → 功能Bug
- 页面显示异常但不涉及敏感数据 → 不是安全漏洞

---

### 🔴 原因九：第三方组件/通用软件漏洞

**审核反馈**："第三方软件通用漏洞暂不接收。"

**TSRC明确说明**：
> "暂停接收第三方软件通用漏洞，建议您向软件官方以及国家相关漏洞平台报告。"

部分SRC只收与自身业务直接相关的漏洞，通用组件漏洞（如某个开源框架的漏洞）如果无法证明对目标SRC有直接影响，很可能被拒绝。

---

### 🔴 原因十：沟通方式不当导致关系恶化

**审核反馈**：（较隐晦，但确实发生）

**真实失败案例**：
- 漏洞被拒绝后，有些白帽子反复在评论区刷屏质疑
- 对审核人员进行言语攻击或辱骂
- 在技术社区公开传播未修复的漏洞细节

**TSRC明确规定**：
> "对于虚构事实、恶意抹黑TSRC平台，或对平台审核运营人员实施言语攻击、辱骂威胁等行为，我们有权取消相关漏洞奖励，将已发放奖励予以追回；封禁涉事平台账号。"

---

## 2. 时间浪费排行榜——新人在哪些地方白费功夫

基于各社区数千条讨论和过来人经验，以下是新人在SRC挖洞中最容易浪费时间的模式：

### 🏆 第1名：无脑跑扫描器（最致命）

**症状**：打开AWVS/AppScan，对着目标域名全量扫描，等几个小时扫出一堆报告，然后逐条手工验证。

**为什么浪费**：
- 重型扫描器产生大量误报 → 新人没有能力区分真假
- 目标SRC有WAF/防护 → IP被封，账号被关联封禁
- 扫描器能扫到的都是"别人也扫得到"的 → 大概率重复
- 扫描报告根本无法直接提交 → 还需要手工验证 → 时间翻倍

> "很多人觉得难是因为没有洞察力、思考力以及大局观。" — 安全客·新手分享

**替代方案**：手工测试 + 轻量级辅助工具（BBScan、JSFinder等），聚焦具体功能点。

---

### 🏆 第2名：在不收的漏洞类型上死磕

**症状**：某个SRC明确写了"不收反射型XSS"，新人仍然花一整天在找反射型XSS。

**为什么会犯**：
- 没读SRC规则就直接开始测试
- 只看了一部分规则，没看完整
- 不知道每个SRC的"忽略清单"不同

> "如果网站根本不收反射型XSS，你却在一直尝试，岂不是浪费时间。" — 安全客·新手漏洞挖掘

**替代方案**：测试前必做：**花10分钟读完该SRC的评分标准PDF**，避免无效劳动。

---

### 🏆 第3名：只盯着大厂核心业务

**症状**：只挖阿里、腾讯、字节、百度等顶级SRC的核心业务（淘宝、微信、抖音等）。

**为什么是坑**：
- 顶级SRC核心业务的安全防护等级最高，新人几乎没有机会
- 这些业务被几百甚至几千个白帽子同时测试
- 一个漏洞从出现到被提交可能只有几个小时窗口

**替代方案**：
- 先从"小而美"的SRC开始（教育SRC、政务SRC、中型企业SRC）
- 关注冷门资产（子公司、边缘业务、旧系统、测试站点）
- "边缘段一般存在测试机器，测试机器往往不关闭debug，登录账号常为弱口令"

---

### 🏆 第4名：花大量时间做"完美信息收集"

**症状**：新人看了大神的文章说"渗透测试的本质是信息收集"，于是花一周时间收集子域名、IP段、端口信息，结果还没开始测漏洞工具就把IP都扫封了。

**为什么是坑**：
- 信息收集没有终点，容易陷入"收集癖"
- 收集到的信息很多对实际漏洞挖掘帮助不大
- 信息收集不应该超过总时间的30%

> "信息收集本身就能发现不少漏洞。" — Tencent Cloud·SRC经验

**替代方案**：20%信息收集 + 60%漏洞测试 + 20%扩线，快速迭代。

---

### 🏆 第5名：无效的漏洞"组合"

**症状**：试图把一个毫无关系的低危漏洞和另一个低危漏洞组合成"高危"。

**为什么是坑**：
- 漏洞组合需要合理的攻击链路，不是随便拼凑
- SRC审核有明确规则："由同一漏洞源产生的多个问题算一个漏洞"
- "从一个漏洞能getshell才算高危，两个Self-XSS拼不成一个高危"

---

### 🏆 第6名：跟风热门漏洞类型

**症状**：Log4j火了就全跑去测Log4j，Spring4Shell火了又全网测Spring。

**为什么是坑**：
- 热门漏洞的POC全网公开，所有人都能测
- 你能测到的别人早就提交了
- 等你去测的时候大概率已经是"已修复"或"已重复"

---

### 🏆 第7名：沉迷于"造轮子"和工具开发

**症状**：花几个月自己写漏洞扫描工具、写自动化脚本，而不是先学会挖洞。

**建议**：先用现成工具（Burp Suite、SQLMap、FFUF等）把流程跑通，再考虑自动化。工具只是手段，不是目的。

---

### 🏆 第8名：花太多时间在非目标功能上

**症状**：在目标网站上体验业务流程、阅读帮助文档、研究产品功能。

**高效做法**：直接关注"交互点"——表单、接口、参数、请求/响应。理解业务流程只需了解"输入-处理-输出"即可。

## 3. 心理陷阱——为什么大多数人坚持不下来

### 🧠 陷阱一："三天打鱼两天晒网"

**表现**：第一周热情高涨每天挖5小时，第二周发现一无所获就放弃。

**数据支撑**：调查显示**31.2%的白帽子进入安全圈不到1年**就退出了，其中很多人是在前3个月一无所获后放弃的。

> "要做好几天可能一无所获的心理准备。" — 安全客·新手漏洞挖掘

**本质原因**：SRC挖洞是**非线性回报**的工作。可能前两周一无所获，第三周突然发现一个高危漏洞。

---

### 🧠 陷阱二："幸存者偏差"错觉

**表现**：看到排行榜上大佬月入10万+，觉得自己也能很快做到。

**真相**：
- 排行榜上的人不到白帽子总数的0.1%
- 8.0%的白帽子提交了500+漏洞
- **60.7%的白帽子月挖洞收入低于300元**
- 大多数"月入过万"的人背后是3年以上的积累

---

### 🧠 陷阱三：攻击心态误区——"我一定要挖到高危"

**表现**：看不起低危漏洞，非要挖到RCE才提交，结果几个月颗粒无收。

**后果**：错过了从低危到中危建立信心和熟悉流程的过程。

> "很多SRC大佬新手阶段都是从逻辑漏洞开始的…可以尝试一些并发的逻辑漏洞，每个网站都或多或少会存在一些。" — 安全客

**建议路径**：短信轰炸 → swagger泄露 → 反射型XSS → 逻辑漏洞 → 越权 → SQL注入 → 高危/严重

---

### 🧠 陷阱四："大师傅依赖症"

**表现**：不好好学习基础，到处加群问"哪里有洞挖"、"教我怎么挖洞"。

> "不要企图去加一下大师傅去骚扰他们，让大师傅们分享怎么快速挖洞的技巧。没有一步登天的好事，所有的坑都需要自己去踩。" — 安全客

> "找大师傅们尽量听他们给的建议，而不是说一味的去问怎么挖洞，这种问题就相当于，一个小孩还不会写字，在让你教他写作文一样。"

---

### 🧠 陷阱五：被拒后的"情绪崩溃"

**表现**：提交一个漏洞，被拒绝了，就觉得"这个SRC不公平"，"审核乱评分"，于是放弃或与审核争吵。

**实际**：
- 被拒绝是常态，哪怕大佬也不例外
- 90%的拒绝是有合理原因的，先反思自己报告的问题
- "提交SRC总有被忽略的时候，不要灰心丧气，年轻的程序员从来不缺重头再来的勇气"

---

### 🧠 陷阱六："一夜暴富"幻想

**表现**：以为挖洞很快就能月入几万，辞职全职挖洞。

**真相**：
- "靠挖洞养家糊口的白帽子，目前来说还只是极少数"
- "大多数白帽子全职挖洞是养不活自己的"（CSDN调研）
- 顶级SRC如腾讯TSRC，一个高危漏洞奖金约2000-6000元，不是每个高危都能到手

---

### 🧠 陷阱七：家人不理解导致的心理压力

**数据**：
- 近一半白帽子的家人不清楚他们在做什么
- 16%以上的家人"不太理解或非常不理解"
- 仅13.4%的家人"非常理解支持"

**影响**：长期不被理解 → 自我怀疑 → 放弃。这是少数被数据证实的致命心理因素。

---

### 🧠 陷阱八：过度自我怀疑

**表现**：看到大厂的产品，就在心里想"这天天用的大网站怎么可能有漏洞"。

> "敢于对你平常使用的东西发起挑战，不要从心理上就把自己吓跑了。" — 安全客

**事实**：互联网产品每天都有新功能上线，新功能 → 新漏洞。只要有人写代码，就有漏洞。

## 4. 收入真相——普通猎人到底能赚多少

### 📊 核心数据（来源：2018白帽调查报告 + 2020白帽调查报告 + 各社区调研）

| 收入区间 | 白帽子占比 | 说明 |
|---------|-----------|------|
| 月挖洞收入<300元 | **60.7%** | 绝大多数人，基本等于玩的 |
| 月挖洞收入>1000元 | **20%** | 有一定能力，但不算主业 |
| 月挖洞收入>3000元 | **<10%** | 已经是有经验的白帽子了 |
| 月挖洞收入>10000元 | **约1-2%** | 排行榜上的"职业选手" |

### 📊 按年度看

| 年份 | 人均漏洞赏金年收入 | 来源 |
|-----|-------------------|------|
| 2021年 | ~57,679元/年 | 奇安信白帽报告 |
| 2022年 | ~31,573元/年 | 奇安信白帽报告（同比下降45%） |

**注意**：2022年平均收入断崖式下降45%，这意味着竞争加剧、漏洞越来越难挖。

### 📊 学生白帽子的收入

- 约20%学生月入3000-8000元
- 约6%学生月入8000-20000元
- 大部分学生月入<3000元甚至无固定收入

### 📊 企业愿意为高危漏洞付多少钱

| 企业支付意愿 | 占比 |
|------------|------|
| 单个高危1000-3000元 | 29.1% |
| 单个高危3000-10000元 | 25.2% |
| 单个高危10000元以上 | 22.0% |

**注意**: 这是"企业愿意付"的数据，不代表白帽子实际能拿到。实际拿到手通常比企业预算低。

## 5. 不值得投入的目标清单

基于社区经验和各大SRC规则，以下类型的目标**大概率白费时间**：

### 高优先级避开（浪费时间最多）

| 类型 | 原因 |
|------|------|
| **大厂核心业务** | 防护最强、竞争最激烈、新人基本没机会 |
| **已被大量白帽子持续测试3年以上的老业务** | 漏洞早就被挖干净了 |
| **不收反射型XSS的SRC的XSS测试** | 违反规则、浪费精力 |
| **只收录高危以上漏洞的SRC的低危测试** | 比如某些合资公司的SRC只收高危 |
| **需要爆破6位以上验证码的逻辑漏洞** | 人力/时间成本与实际危害不匹配（看云SRC明确说不收） |

### 中优先级避开（收益低/容易违规）

| 类型 | 原因 |
|------|------|
| **外包/三方服务** | 多数SRC不收，问了也白测 |
| **已停止维护的老系统** | 喜马拉雅SRC明确说"不再更新维护的客户端产品不予以计分" |
| **测试环境/演示站点** | 即使有漏洞也通常不收录 |
| **手机验证码爆破类** | 耗时巨大、成功率低、容易触发风控封号 |
| **已被团队扫烂的边缘资产** | OneForAll + Xray + Goby 一套组合拳下来，冷门也变热了 |

### 低优先级避开（除非有独特思路）

| 类型 | 建议 |
|------|------|
| **已公开的供应链漏洞** | 全网都能测，你大概率是第100个 |
| **CTF风格的刁钻漏洞** | 实战中极少遇到，遇到了也很难利用 |
| **需要极高权限才能利用的漏洞** | 比如果壳级代码审计，靠这个吃饭的人不需要看此文 |

## 6. 新人避坑行动清单

### ✅ 入门阶段（第1-3个月）

- [ ] **精读3个SRC的评分标准**：选一个中型SRC（如58SRC、猎聘SRC）+ 一个大型SRC（如TSRC）+ 一个众测平台（补天），读透它们的"忽略清单"
- [ ] **先从"必收"的漏洞类型开始**：GitHub信息泄露、swagger未授权、弱口令
- [ ] **每个报告写好再提交**：花1小时写一个好报告，胜过3个小时写一个差报告
- [ ] **不要碰大厂核心业务**：先在教育SRC、政务SRC、小众企业SRC练手

### ✅ 进阶阶段（第3-12个月）

- [ ] **建立自己的"失败笔记"**：记录每一次被拒的原因，三个月后回头看
- [ ] **学会漏洞扩线**：挖到一个低危 → 思考如何提升危害（XSS+CSRF=蠕虫、弱口令+shell=多个高危）
- [ ] **参与众测项目**：漏洞盒子/补天的众测项目收入比单纯SRC高
- [ ] **建立技术输入习惯**：每天读一篇案例文章（安全客/先知/Freebuf）

### ✅ 心理建设清单

- [ ] 接受**前3个月0收入**（80%新人的真实状态）
- [ ] 接受**60%的提交被拒绝**（这是常态）
- [ ] **不和大佬比收入**（你能看到的是幸存者偏差）
- [ ] **被拒绝后先反思自己**，再质疑审核
- [ ] 把SRC当作**学习工具**，不是赚钱工具
