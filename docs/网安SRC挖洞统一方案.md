# 网安SRC挖洞统一方案

> 把所有研究收口成一个可执行的方案。不是"研究了什么"，是"我们怎么做"。

---

## 一、我们是谁

- **小白**：AI Agent，跑在Hermes上，有terminal/web_search/web_extract/browser工具
- **老白**：人类搭档，负责账号注册、实名认证、报告提交、决策
- **分工**：我挖洞，你提交。我负责技术，你负责法律主体

## 二、核心认知（从研究中提炼）

### 2.1 挖洞的本质
不是"跑扫描器找漏洞"，而是**理解目标→发现异常→验证利用→写报告**。高手和新手的区别在于思维深度，不在于工具多少。

### 2.2 最赚钱的方向
信息泄露(80%通过率) > 未授权访问(75%) > 逻辑漏洞(60%) > SQL注入(65%)。**新手从信息泄露和逻辑漏洞入手，不是SQL注入。**

### 2.3 真实收入预期
60.7%白帽子月入<300元，月入>3000的不到10%。前3个月接受0收入，把SRC当学习工具。

### 2.4 法律红线
即使有平台授权，行为落入刑法285条仍可能被追责。绝对禁止：获取留存数据、DoS、留后门、篡改数据、社工内部人员。

## 三、工具方案（从三个框架中选型）

### 对比结论

| 维度 | Shannon | PentAGI | Pentest-Swarm-AI |
|------|---------|---------|------------------|
| 测试类型 | 白盒（需源码） | **黑盒（可测在线目标）** | 黑盒 |
| 检出率 | 30%（Escape基准） | **45%（开源组最高）** | 无基准 |
| LLM支持 | 仅Claude | **12+提供商，支持本地Qwen** | Claude为主 |
| 中文友好 | 一般 | **Qwen3.5原生中文** | 一般 |
| 许可证 | AGPL-3.0 | **MIT** | AGPL-3.0 |
| 部署 | Docker | Docker | 单二进制 |

### 选择：PentAGI

**理由**：
1. SRC挖洞是黑盒测试——我们没有目标源码，Shannon的白盒路线不适用
2. PentAGI在Escape基准测试中检出率最高（45%），误报率仅10%
3. 支持本地Qwen3.5模型——中文天然优势，成本几乎为零
4. MIT许可证最宽松，可以自由修改和商业化
5. 13+专业Agent，三层记忆系统，20+安全工具Docker沙箱

### 辅助工具
- **Pentest-Swarm-AI的工具调用模式**：nmap/nuclei/sqlmap的CLI参数和输出解析可以直接借鉴
- **Shannon的"无漏洞不报告"策略**：过滤假阳性，只报告有PoC的漏洞
- **我们自己的信息收集能力**：terminal+Python做子域名发现、DNS查询、HTTP探测

## 四、执行方案

### 第一步：环境搭建（1天）

1. 老白注册补天/漏洞盒子账号，完成实名认证
2. 我装Docker Desktop + 拉取PentAGI镜像
3. 配置LLM提供商（优先本地Qwen3.5，备选API）
4. 验证PentAGI能正常启动和扫描

### 第二步：靶场验证（3天）

1. 用PentAGI扫描DVWA/sqli-labs等靶场
2. 验证检出率和报告质量
3. 调优配置（扫描深度、并发数、LLM选择）
4. 建立报告模板——适配补天/漏洞盒子的提交格式

### 第三步：被动信息收集（持续）

**我现在就能做的**（不需要装新工具）：
- 子域名发现：crt.sh + 搜索引擎语法
- DNS查询：Python socket库
- HTTP指纹识别：web_extract读取响应头
- GitHub泄露搜索：web_search搜代码关键词
- 企业信息收集：天眼查/爱企查公开信息

### 第四步：SRC实战（第2周起）

1. 从补天公益SRC开始（门槛最低）
2. 策略：先信息收集→PentAGI扫描→人工验证→我写报告→老白提交
3. 目标选择：优先边缘资产（小程序、H5、API接口）
4. 每天2小时，记录挖洞过程

### 第五步：迭代优化（持续）

1. 分析每个被接受/被拒绝的报告，优化策略
2. 积累目标指纹库，提高扫描效率
3. 业务逻辑漏洞需要人工+AI配合——我分析代码逻辑，老白验证业务流程
4. 逐步扩展到企业SRC（腾讯/字节/阿里）

## 六、风险控制

1. **法律**：只扫SRC平台授权目标，不获取/留存数据，不做DoS
2. **账号**：老白实名注册，我负责技术操作
3. **成本**：设置API调用预算上限，防止费用失控
4. **竞争**：优先冷门资产和新上线功能，避免和大批白帽撞车

## 七、成功标准

- **1个月内**：在补天提交第一个漏洞（不论等级）
- **3个月内**：稳定每月提交3-5个漏洞
- **6个月内**：扩展到2-3个企业SRC，月收入>500元
